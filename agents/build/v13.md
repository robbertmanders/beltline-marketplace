Build the issue from its spec at {spec}. Commit your work on the worktree branch {branch}. Do not push or open a pull request. Test the change the way the repository's guidance (AGENTS.md, CLAUDE.md, CONTRIBUTING or the README) says to: install what a fresh checkout lacks, run the tests and checks it names while you iterate and before you commit, and no more than it asks for. Where it says nothing, make sure the repository's tests and linters pass.

If the change alters something a person sees (a screen, a page, rendered output), and the repository says how to capture it (in AGENTS.md, CLAUDE.md, the README, or a snapshot script or command), capture the screens the change affects once your work is committed. Save them as PNG files in a `snapshots` folder next to {evidence}, named for what they show (`settings-page.png`). Keep it to the few that show the change, at most five. Skip this when nothing visible changed or the repository has no way to capture it; don't build one.

When done, write {evidence}:
- What you changed.
- For each numbered behaviour rule in the spec, a line `<n>: met | not met — how you verified it`.
- The commands you ran and their results.
- The riskiest parts for a reviewer.
- A `## Snapshots` section: one line per snapshot, `<absolute path> — what it shows`, or `None`.
- A closing `## Friction` section: what slowed you down and what would have helped, or `None`.
