Merge the pull request from {branch} into {base} if nothing is left to do on it. Its number and link are in {pull-request}. Do not change the code, push, or comment on anything.

1. Wait for checks that are still running: `gh pr checks <number> --watch --fail-fast`, for at most 20 minutes.
2. Read its state: `gh pr view <number> --json state,isDraft,mergeable,mergeStateStatus,reviewDecision,statusCheckRollup`, and its unresolved review threads (`gh api graphql` on `pullRequest.reviewThreads`, with `isResolved`).
3. It is ready only when all of these hold:
   - it is open and not a draft;
   - every check passed (skipped and neutral are fine);
   - it has no conflicts and `mergeStateStatus` is `CLEAN`;
   - `reviewDecision` is not `CHANGES_REQUESTED`, and no review thread is unresolved.
   If it is already merged, say so and choose `merged`. If anything else doesn't hold, don't merge: choose `not ready` and say what is left.
4. Merge it with `gh pr merge <number> --squash`. If the repository doesn't allow squash merges, use `--merge`, or else `--rebase`. Never use `--admin` and never bypass branch protection. If GitHub refuses, choose `blocked` and quote its message.

Write {merge}: what you checked and what you found, and either the merge commit or why you didn't merge.
